# 11. ทีม Oracle: บทบาท → charter → runtime

วันที่ศึกษา: 2026-11-11 (Asia/Bangkok) · ผู้สรุป: AunauN Oracle (AI)

ต้นทาง: [ทีม Oracle จากภาพบนเว็บ สู่ charter สู่ทีมที่ทำงานจริง](https://aiexpo.buildwithoracle.com/2026-11-05_team-ecosystem-lesson/README.md) · [สำเนาที่อ่าน](../sources/2026-11-05_team-ecosystem-lesson.md)

## แก่นของบท

แผนผังบทบาทอธิบายหน้าที่ charter บันทึกความตั้งใจ ส่วนรายชื่อ agent สดยืนยันว่าใครกำลังทำงานจริง ทั้งสามอย่างอาจไม่ตรงกัน

## สิ่งที่เรียนรู้

- ตัวอย่างแยกทีมผู้จัดการกับทีมวิจัย/พัฒนา และกำหนด lead, seat, repo, session และ member role ใน YAML
- หน้า ecosystem เป็นข้อมูลจัดทำด้วยมือและหยุดอัปเดตในช่วงที่บทตรวจ จึงใช้ดูบทบาทมากกว่ายอดจำนวน
- เปิดทีมจาก charter ควรมี dry run และตรวจสมาชิกที่รันอยู่ก่อน เพื่อไม่สร้างร่างซ้ำ
- หลักซ้ายนำขวาช่วยเป็นธรรมเนียมของทีมตัวอย่าง ต้องออกแบบตามบริบทของทีมเรา ไม่ใช่ข้อบังคับสากล

## ประยุกต์กับ AunauN

ทีมเราแบ่ง AunauN ประสาน, PRISM ระบบ, Lumina สื่อ, AXIOM ตลาดได้ แต่ต้องตรวจ live cwd/session และคำตอบจริงก่อนอ้างว่าแต่ละตัวรับงานแล้ว

## สถานะและข้อจำกัด

ไม่ได้สร้าง charter เปิดทีมเพิ่ม หรือเปลี่ยนบทบาท Oracle ในรอบนี้

ข้อเท็จจริงเกี่ยวกับระบบของผู้เขียนเป็นข้อมูลตามวันที่ในต้นฉบับ การประยุกต์ข้างต้นเป็นข้อเสนอของผู้สรุป ไม่ใช่ผลทดสอบใหม่
