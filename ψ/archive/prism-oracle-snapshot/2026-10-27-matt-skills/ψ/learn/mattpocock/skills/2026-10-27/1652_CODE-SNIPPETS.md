# รูปแบบวิธีทำงานจาก engineering skills

ศึกษาซอร์ส `mattpocock/skills` ที่ commit `59db609eb1e18aaf59b63284d0e52255aff0c63c` เนื้อหานี้เป็นการอ่านคำแนะนำ ไม่ได้ติดตั้งหรือเรียกใช้สกิล และไม่ใช่ผลทดลองกับงาน PRISM

## ทดลองแนวคิดผ่าน prototype

[`prototype/SKILL.md`](../origin/skills/engineering/prototype/SKILL.md) แยกคำถามสองแบบ: ทดลองตรรกะหรือ state model ด้วย HTML ที่ผู้ใช้กดเล่นและติดตามสถานะได้ กับทดลองหน้าตา UI หลายรูปแบบบน route เดียว สกิลเสนอให้ระบุว่าเป็น prototype และทำให้เริ่มทดลองได้ง่าย โดยเริ่มจากคำถามที่ต้องการตอบ

**ตัวอย่างสำหรับ PRISM:** ก่อนสร้างหน้าจอจองท่องเที่ยว อาจทำตัวอย่างที่กดเปลี่ยนวัน จำนวนผู้เดินทาง และสถานะห้อง เพื่อดูว่าลำดับการตัดสินใจเข้าใจง่ายหรือไม่ แล้วบันทึกข้อสรุปที่ตรวจได้ก่อนพัฒนาต่อ

## ตรวจบั๊กด้วย feedback loop

[`diagnosing-bugs/SKILL.md`](../origin/skills/engineering/diagnosing-bugs/SKILL.md) เริ่มจากสร้างวิธีตรวจที่แสดงอาการผิดพลาดได้จริง ลดกรณีให้เล็ก ตั้งสมมติฐานที่หักล้างได้และตรวจทีละข้อ จากนั้นยืนยันผลแก้ไขกับกรณีเดิมและเก็บ regression test เมื่อมีจุดทดสอบที่เหมาะสม เน้นลบข้อมูลลับออกจาก output

**ตัวอย่างสำหรับ PRISM:** ถ้าตัวกรอง dashboard แสดงผลผิด ให้เริ่มจากชุดข้อมูลตัวอย่างกับขั้นตอนที่ทำให้จำนวนผิดซ้ำได้ แล้วทดสอบก่อนและหลังแก้โดยตรวจผลที่ผู้ใช้เห็น

## ทดสอบพฤติกรรมที่ผู้ใช้เห็น

[`tdd/SKILL.md`](../origin/skills/engineering/tdd/SKILL.md) เสนอวงจร red → green ทีละชิ้น โดยทดสอบผ่าน interface ที่สังเกตพฤติกรรมได้ และระวัง test ที่ผูกกับรายละเอียดภายในหรือคำนวณผลคาดหมายด้วยสูตรเดียวกับ implementation สกิลต้นฉบับระบุให้ตกลงจุดทดสอบกับผู้ใช้ก่อน; ในงานจริงต้องปฏิบัติตามคำสั่งผู้ใช้และข้อกำหนดของ host ที่มีผลอยู่

**ตัวอย่างสำหรับ PRISM:** ตรวจว่ากดบันทึกแผนงานแล้วหน้าจอแสดงสถานะใหม่ แทนการยืนยันเฉพาะว่าฟังก์ชันภายในถูกเรียก

## ตรวจงานสองมุม

[`code-review/SKILL.md`](../origin/skills/engineering/code-review/SKILL.md) เสนอให้กำหนดจุดอ้างอิงของ diff และตรวจสองมุมแยกกัน: ความสอดคล้องกับมาตรฐานของ repository และความครบถ้วนตาม spec โดยตรวจว่า ref ใช้ได้และ diff ไม่ว่างก่อน สกิลต้นฉบับใช้ผู้ช่วยแยกสองสาย; การใช้ผู้ช่วยจริงขึ้นกับความสามารถและข้อกำหนดของเซสชัน

[`to-spec/SKILL.md`](../origin/skills/engineering/to-spec/SKILL.md) เสนอแปลงบริบทสนทนาเป็น spec ที่มีปัญหา ทางแก้ user stories ขอบเขต และการทดสอบ โดยต้นฉบับรวมการเผยแพร่ไป issue tracker ซึ่งเป็นการกระทำภายนอกและต้องมีคำสั่งที่อนุญาตก่อน

## ข้อจำกัด

คำแนะนำเหล่านี้ช่วยตั้งกรอบการทำงาน แต่ไม่ใช่ผลทดสอบว่ากระบวนการเหมาะกับทุกงาน บางสกิลมีขั้นตอนเฉพาะ เช่น issue tracker, parallel agents หรือการ commit ซึ่งต้องตรวจความพร้อมและทำตามขอบเขตที่ผู้ใช้อนุญาตก่อนเสมอ
