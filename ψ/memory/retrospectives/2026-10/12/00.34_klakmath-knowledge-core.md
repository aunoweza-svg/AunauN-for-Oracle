## 💭 Honest Feedback

1. **Process friction:** The session mixed repository recovery, codebase learning, visual design, responsive QA, and deployment discussion in one continuous thread. The outcome is coherent, but the boundaries were not explicit early enough. A better process would declare three checkpoints—learn, build, publish—and verify repository safety before moving from one checkpoint to the next.

2. **Tool friction:** Several expected tools were missing or unavailable: `ghq`, Git in PATH, Node, Python, a supported local HTTP listener, and a controllable browser. The fallbacks worked, but each fallback increased verification complexity. A small environment preflight would have reduced repeated discovery and prevented the preview workflow from changing midway through implementation.

3. **Communication friction:** I said the site was responsive after desktop validation before the mobile viewport evidence was fully reliable. Although responsive CSS was present, the Windows display scaling made the screenshots ambiguous. I should have described that distinction precisely: “responsive rules implemented; desktop visually verified; mobile verification limited by effective viewport scaling.” That wording would have been more truthful and easier for the user to trust.

## Lessons Learned

- **Pattern**: เมื่อสอน codebase ที่ผู้ใช้ไม่รู้จัก ให้ map แนวคิดใหม่เข้ากับ mental model ที่เขารู้ แล้วสร้าง interactive artifact ที่ทำให้ input/state/output มองเห็นได้.
- **Mistake**: อย่าแก้ responsive CSS จาก screenshot จนกว่าจะยืนยัน effective CSS viewport, device scale และ scroll state.
- **Discovery**: Canvas 2D เพียงพอสำหรับ knowledge globe แบบหมุนได้ที่มี node projection และ edges โดยไม่ต้องเพิ่ม Three.js หรือ WebGL framework.
