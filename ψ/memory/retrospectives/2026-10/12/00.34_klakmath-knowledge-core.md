## 📝 AI Diary

I began the session thinking the main task would be simple repository orientation, but it quickly became a bridge-building exercise between two technical worlds. The user understands web development but not Unity or the equations in KlakMath, so a conventional code summary would have been accurate yet not especially useful. My approach changed from merely cataloging files to constructing a translation layer: easing became tweening, application state became value-plus-velocity, smooth procedural motion became noise, and stable avatar-like identity became seeded hashing. The parallel repository reading worked well because each document had a narrow role and cited source paths. The contamination scan was important; it gave me confidence that the reports described KlakMath rather than the host Oracle repository.

The visual direction became clear once the user asked for a JARVIS-like knowledge globe. A dependency-free Canvas implementation felt honest to the “basic HTML” request while still producing an ambitious result. The strongest moment was seeing the first desktop screenshot render correctly: the graph was not just decoration, but a navigable model of the source architecture.

[→ AGENT DECISION] I made the wrong decision to keep interpreting Windows headless Chrome screenshots as true mobile CSS viewports before accounting for display scaling. ## Blockers & Resolutions

- **`ghq` unavailable** — ตรวจด้วย command discovery แล้วไม่พบ; แก้โดย clone ไป `.learn-sources/github.com/keijiro/KlakMath` และสร้าง junction แยกจาก docs. ความเสี่ยงคงเหลือคือ workflow นี้ไม่ใช่ canonical `ghq` layout.
- **Git ไม่อยู่ใน PATH** — คำสั่ง `git` ปกติล้มเหลว; แก้ด้วย `C:\Program Files\Git\cmd\git.exe`. ความเสี่ยงคือคำสั่งใหม่ต้องใช้ full path จนกว่า PATH จะถูกตั้งค่า.
- **Node, Python server, HttpListener และ CUA browser ใช้งานไม่ได้** — ใช้ Chrome headless กับ `file://` เพื่อตรวจภาพ และเปิด Chrome visible ให้ผู้ใช้แทน. ความเสี่ยงคือ automated interaction tests ยังไม่มี.
- **Local/remote history ไม่ตรงกัน** — local `main` ยังไม่มี commit แต่ remote มี `main`; ยังไม่แก้เพื่อหลีกเลี่ยงการทับข้อมูล. ต้อง sync ผ่าน clean clone ก่อนเผยแพร่.

## 💭 Honest Feedback

1. **Process friction:** The session mixed repository recovery, codebase learning, visual design, responsive QA, and deployment discussion in one continuous thread. The outcome is coherent, but the boundaries were not explicit early enough. A better process would declare three checkpoints—learn, build, publish—and verify repository safety before moving from one checkpoint to the next.

2. **Tool friction:** Several expected tools were missing or unavailable: `ghq`, Git in PATH, Node, Python, a supported local HTTP listener, and a controllable browser. The fallbacks worked, but each fallback increased verification complexity. A small environment preflight would have reduced repeated discovery and prevented the preview workflow from changing midway through implementation.

3. **Communication friction:** I said the site was responsive after desktop validation before the mobile viewport evidence was fully reliable. Although responsive CSS was present, the Windows display scaling made the screenshots ambiguous. I should have described that distinction precisely: “responsive rules implemented; desktop visually verified; mobile verification limited by effective viewport scaling.” That wording would have been more truthful and easier for the user to trust.

## Lessons Learned

- **Pattern**: เมื่อสอน codebase ที่ผู้ใช้ไม่รู้จัก ให้ map แนวคิดใหม่เข้ากับ mental model ที่เขารู้ แล้วสร้าง interactive artifact ที่ทำให้ input/state/output มองเห็นได้.
- **Mistake**: อย่าแก้ responsive CSS จาก screenshot จนกว่าจะยืนยัน effective CSS viewport, device scale และ scroll state.
- **Discovery**: Canvas 2D เพียงพอสำหรับ knowledge globe แบบหมุนได้ที่มี node projection และ edges โดยไม่ต้องเพิ่ม Three.js หรือ WebGL framework.
