## 📝 AI Diary

I began this work with a clear distinction between studying a repository and installing something that can actually run. The user had already asked PRISM to learn both projects, and then explicitly requested installation. I checked the prior records first and found that the earlier REA installation belonged to a different workspace that no longer existed at its recorded path. I therefore chose workspace-local runtimes and checked the downloaded archives against their published checksums rather than assuming an old installation was still available.

The UI skill installed from the pinned source, but the first search failed because the embeddable Python distribution did not include the script directory in its import path. A small wrapper made that relationship explicit and the design-system search then returned a result. REA presented a different problem: package installation and configuration succeeded, and a separate MCP handshake listed tools, but a real JavaScript analysis encountered a Windows Application Control block. Those facts belong together in the record: a tool list is not proof that the target operation works.

[→ AGENT DECISION] I initially tried the Python search directly without checking the import behavior of the embeddable distribution. That created an avoidable failure. Next time I should validate interpreter path behavior before claiming that a portable runtime is interchangeable with a regular installation. I also preserved the security boundary rather than treating disabling Windows protection as a routine fix.

## 💭 Honest Feedback

1. **Installation prerequisites:** The old REA installation record described a valid setup in a previous workspace, but those paths no longer existed on this machine. Checking the actual paths early prevented an inaccurate reuse claim. A portable setup is useful here, but it creates a duty to document where binaries live and how a new machine can rebuild them.

2. **Runtime verification:** The first UI test exposed an import-path difference that the package installation itself did not reveal. The wrapper made the test pass, but it also means future users must invoke the documented command or set up a normal Python environment. A successful file copy alone would have hidden that problem.

3. **REA readiness:** Configuration and the MCP tool inventory were healthy while the real analysis was blocked by Windows policy. The partial response was large, and treating it as a simple success would have overstated capability. Future work should use concise evidence summaries, test a representative operation, and describe the native-policy blocker separately from provider installation.

## Lessons Learned

- **Pattern:** ตรวจ installation, registration, MCP connection และ representative operation เป็นคนละชั้น
- **Mistake:** อย่าสมมติว่า Python embeddable มี import path เหมือน interpreter ปกติ
- **Discovery:** system CA แก้ npm TLS ในสภาพแวดล้อมนี้ได้โดยไม่ปิดการตรวจใบรับรอง

## Recurring Pattern

เจ็ดแถว metrics ล่าสุดมี friction เรื่อง prerequisites หรือความพร้อม runtime อย่างน้อยสามรอบ (REA/marketing, finance tools, hardware assessment และการติดตั้งครั้งนี้) ควรตรวจ runtime และทดสอบ operation ตัวอย่างก่อนรับรองความพร้อม
