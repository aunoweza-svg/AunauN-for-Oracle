## What Went Well

- ตรวจ identity ทั้งสอง Oracle จากไฟล์จริง และไม่รวมสำเนา awaken ซ้ำเป็นตัวใหม่
- PRISM มีตัวตน หลักการ และความจำ พร้อมเอกสารเรียนรู้ที่ชี้ไปยัง source commit
- แยกการศึกษาจากการติดตั้ง และไม่เรียกใช้ target หรือ provider ที่ยังไม่ได้ตรวจ

## What Could Improve

- วางแผนการสำรอง repo แยกตั้งแต่ก่อนสร้าง และระบุว่าซอร์สที่ ignore ต้อง clone ใหม่ได้อย่างไร
- อ่านเฉพาะส่วนที่จำเป็นแทนการส่ง README หรือรายการไฟล์จำนวนมากจน output ถูกตัด

## Blockers & Resolutions

- Clone ภายใน sandbox ล้มเหลวด้วย schannel; รันใหม่ผ่านขั้นตอนอนุญาตระบบและตรวจ source commit สำเร็จ
- PRISM ไม่มี remote และยังไม่มี commit; snapshot ใน repo หลักเตรียมให้ซิงก์ แต่ไม่ได้สร้าง remote หรือเผยแพร่ไป repo อื่น

2. **ขอบเขต Git:** repo PRISM ถูกสร้างภายใน repo หลักและไม่มี remote โครงสร้างนี้เหมาะกับการแยกตัวตน แต่ทำให้กติกา push ของ repo หลักไม่สามารถส่งประวัติ Git ของ PRISM ได้โดยตรง Snapshot แก้เรื่องสำรองไฟล์ได้บางส่วน แต่ต้องตรวจเส้นทางและอธิบายวิธีคืนค่า ไม่ควรอ้างว่าซิงก์ repo แยกแล้ว

3. **ขนาดผลลัพธ์เครื่องมือ:** การอ่าน README และรายชื่อไฟล์ทั้งชุดทำให้ผลถูกตัด แม้จะกลับไปอ่านส่วนที่จำเป็นและใช้ผู้สำรวจแยกหัวข้อได้ การเริ่มด้วยสารบัญและค้นเฉพาะจุดจะทำให้ตรวจหลักฐานได้ง่ายกว่าและลดโอกาสหลงประเด็น

## Lessons Learned

- **Pattern:** แยกการศึกษาซอร์ส การติดตั้ง และ runtime proof พร้อมระบุ commit และขอบเขตที่ตรวจ
- **Mistake:** อย่าสมมติว่า Git repo ซ้อนอยู่ใน repo แม่จะถูกสำรองไปพร้อมกัน
- **Discovery:** snapshot ที่ไม่รวม `.git` และ source clones ช่วยสำรองเอกสารโดยไม่แอบอ้างว่าเป็น repo หรือ dependency ที่ติดตั้ง
