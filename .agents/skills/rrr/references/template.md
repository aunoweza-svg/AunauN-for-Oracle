# Retrospective template

Use the following sections, concise for a small session. Light mode retains only metadata, Timeline, Session Summary, Lessons Learned and the metrics row.

```markdown
# Session Retrospective

**Session Date**: YYYY-MM-DD (Asia/Bangkok)
**Start / End**: observed times or unknown
**Duration**: observed active duration or unknown
**Primary Focus**: concrete goal
**Session Type**: type of work
**Repository / Branch**: verified repo / branch
**Current Issue / PR**: links or none
**Session**: attributable ID or unknown
**Evidence Source**: current context, host metadata, Git; limitations and mode

## Session Summary
Goal, outcome, outstanding work.

## Timeline
Observed timestamps for attributable events, untimed bullets for others.

## Technical Details
Files, changes, decisions and verification.

## 📝 AI Diary
First-person assumptions and decisions. Name actual mistaken decisions when present; otherwise none observed.

## What Went Well
Concrete evidence.

## What Could Improve
Specific process improvements.

## Blockers & Resolutions
Actual attempts, outcomes and limitations, or none.

## 💭 Honest Feedback
Session-specific friction; no invented criticism or word quota.

## Lessons Learned
Transferable evidence-backed lessons, or none.

## Next Steps
Unfinished, actionable work.

## Related Resources
Verified paths, commits and links.

## 🔍 Self-Audit
Shipped, blocked, agent decisions, friction, next steps and rationalizations observed.
```

Verify accuracy and scope before saving. Do not append the internal checklist to the retro. Report sync in the final response after checking it; do not prewrite future push success into the file.
